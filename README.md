# Стенд личного кабинета Coral Club

Отдельный проект: окно входа и главная в духе банковского приложения на данных из API личного кабинета. Ни от каких других проектов не зависит.

## Самый простой способ

Откройте папку проекта в Claude Code и напишите: **«Запусти этот проект на локальном сервере и установи всё необходимое, если нужно»**. Claude сам проверит Node, запустит стенд и откроет страницу (инструкции для него в `CLAUDE.md`).

## Вручную

```bash
npm start        # http://localhost:3300 (другой порт: LK_PORT=3310 npm start)
```

Нужны Node.js 20+ и интернет. Зависимостей из npm нет.

### С телефона (та же Wi-Fi сеть)

```bash
LK_HOST=0.0.0.0 npm start
```

В выводе будут адреса вида `http://192.168.x.x:3300`: откройте такой адрес на телефоне. Пароль идёт по http без шифрования, пользуйтесь доверенной сетью. По умолчанию стенд слушает только этот компьютер.

## Без сервера (GitHub Pages и другой статичный хостинг)

Папка `docs/` (её же отдаёт GitHub Pages) выкладывается как есть: API Coral Club (`api.coral.club`) принимает запросы с любых сайтов, поэтому страница сама открывает сессию и входит, токен лежит только в `sessionStorage` вкладки. Сервер `server.mjs` в этом случае не нужен: страница сама определяет, что его нет. Проверить прямой режим локально: `http://localhost:3300/?direct=1`.

## Вход

На странице введите логин и пароль **тестовой учётной записи** кабинета (их даёт владелец проекта). Они уходят только в магазин, на стенде не сохраняются и в лог не пишутся. Сессия хранится в памяти сервера, перезапуск сервера = выход.

## Что на главной

- Основной счёт (баланс), тег «Трансферный счёт» с баллами.
- Быстрые действия: перевод баллов, перевод бонусов, пригласить в клуб. Переводы реальные (перед отправкой есть подтверждение).
- «Мои показатели»: закрытый ранг, география, СОП / СОП\*, групповой объём.
- Клик по основному счёту открывает «Coral Кошелёк»: кнопки «Оплатить бонусами», «Вывести на карту», «Перевести баллы», «Выписка» (CSV для Excel) и «История по счету». Карточки-переходы «История заказов» и «Моя структура» ведут на свои экраны.
- Раздел «Отладка: запросы к API» внизу: любой GET или POST к `/restApi/proxyCC4/…` и просмотр ответа.

## Какие методы API используются

`GET /account`, `/account/checking_accounts?currency=…`, `/account/metrics`, `/account/ref_link`, `/personal-new/transfer/month`, `/personal-new/transfer/check-person`, `POST /personal-new/transfer/create`, `POST /personal-new/transfer/bonus`, `/personal-new/shop/orders`, `/personal-new/wallet/baRep`. Полная документация API: https://api.coral.club/docs

## Как это устроено

- `server.mjs`: маленький сервер на 127.0.0.1. Принимает вход (`/lk/login`), сам ходит в магазин (`coralclub.ru`) с куками и токеном сессии, отдаёт страницы. Пропускает к магазину только `/restApi/proxyCC4/`, `/restApi/auth/`, `/restApi/registration/`.
- `docs/config.json`: адрес магазина, параметры сессии API (`applicationToken` взят из публичного JS кабинета) и список запросов для раздела отладки.

## Магазин и нижнее меню

Нижнее меню: Главная (магазин, продукты гидратации), Каталог, Корзина, Избранное, Профиль (кабинет с балансом, рангами и задачами). Код магазина: `docs/shop.js`.

- Каталог и корзина идут через API кабинета: `GET /catalog/products`, `GET /personal-new/shop?type=`, `GET /basket/quantities`, `POST /basket`, `POST /basket/decrease`, `DELETE /basket/{code}/{memberId}`.
- «Оформить заказ» открывает страницу оформления магазина по ссылке из `GET /web_views/checkout_new` (ссылка содержит доступ, поэтому не показывается и не логируется). Сам заказ создаётся на стороне магазина после подтверждения пользователя.
- Артикулы гидратации для РФ заданы в `HYDRATION` (`shop.js`): 80720, 80380, 2220, 91883. Фото в `docs/img/shop/`, если API не отдал своё.
- Структуры ответов в описании API не заданы: поля читаются осторожно (`normalize`, `parseCart`), сырые ответы лежат в `window.__shopDebug`.
- Избранное хранится в `localStorage` браузера (`lk_fav`).

## Свой чек-аут внутри ЛК (без перехода на сайт)

Вид корзины и оформления перенесён из проекта «Друг клуба»: стили генерируются из его CSS-модулей скриптом `python3 scripts/port-friend-css.py` в `docs/friend.css` (классы с префиксами `ck-`, `lc-`, `oc-`, `sl-`, `ex-`, `cp-`, `ps-`, `cm-`; руками файл не править). Кнопка «Оформить заказ» в корзине открывает `#/checkout` (`docs/checkout.js`).

Что есть на странице оформления:
- переключатель «Доставка / Самовывоз»; адрес с поиском Google (или ручной ввод), пункты выдачи списком с фильтром по службам и поиском;
- контакты из профиля, способы доставки и оплаты карточками, время курьера для Москвы и Санкт-Петербурга (расписание из `/init`);
- промокод (`/sv-api/promo`) и списание бонусов Coral Кошелька (`bonusUseValue`), итог пересчитывается при каждом выборе;
- подтверждение заказа в окне; оплата картой: после заказа прямой переход на страницу банка (шлюз магазина), как в «Друге клуба» для РФ и Германии. Собственная форма карты там только для США, в РФ шлюз её не принимает.

Страна: флаг в хедере магазина и страницы оформления (на профиле и страницах кабинета его нет). Список стран приходит из `/init`, выбор хранится в `localStorage` (`lk_country`).

Как это работает технически:
- Магазин принимает методы чек-аута (`/sv-api/*`) только по своей сессии. Поэтому страница ходит к стенду (`/lk/shop/...`), а `server.mjs` проксирует их в магазин с авторизованной сессией этого входа. Пропускаются только `init, delivery, payments, pickpoints, profiles, receivers, promo, getOrder, order, checkLocality, getProfilePrice`, `shop/shop_basket.php`, `getLocation` и страница оплаты `/order/payment/<id>/`; POST разрешён только на `/sv-api/order`.
- Работает при запуске `npm start` и на GitHub Pages через Cloudflare Worker (раздел ниже). Без того и другого остаётся запасной путь: страница оформления магазина по ссылке из `web_views/checkout_new`.
- Ключ поиска адреса Google (браузерный, с ограничением по HTTP-референту): `GOOGLE_PLACES_KEY` в окружении или в `.env.local` (в git не попадает). Для `http://localhost:3300/*` его нужно разрешить в консоли Google. Без ключа адрес вводится вручную.
- Заказ создаётся только по нажатию «Оформить заказ» в окне подтверждения.
- Не сделано: карта на выбор точки (пункты выдачи только списком), выбор региона из списка, оплата PayPal и Google Pay.
- Сырые ответы чек-аута для отладки: `window.__shopDebug` (`init`, `delivery`, `payments`, `totals`, `pickpoints`).

## Посредник для GitHub Pages (Cloudflare Worker)

Магазин принимает методы чек-аута только по своей сессии (cookie `PHPSESSID`, `HttpOnly`), а браузер с `github.io` не может её ни получить, ни передать. Проверено: ответ магазина на логин не содержит идентификатор сессии, а заголовок `PHPSESSID` вместо cookie магазин не принимает. Поэтому сессию держит Worker. Его код теперь в монорепозитории `coral-club-shop`: пакет `packages/gateway` (`@coral/gateway`), там же офлайн-тесты и описание. Стенд (`server.mjs`) берёт оттуда проход оплаты: по умолчанию из `../coral-club-shop/packages/gateway/src/`.

**Пароль Worker не нужен.** Сессия участника открывается по токену API кабинета. Проверено на реальной сессии: `GET /web_views/checkout_new` возвращает `{ url, access_token }`; запрос к `url` с заголовком `x-access-token: <access_token>` открывает авторизованную сессию магазина (остальные десять способов передать токен не работают). Корзина участника из API при этом видна в корзине магазина (`/sv-api/order` показывает её `QUANTITY`).

Как работает:
- `POST /session` с `Authorization: Bearer <токен API>` → Worker открывает сессию магазина, кладёт её в KV и отдаёт случайный `sid`;
- `GET|POST /shop/<путь>` с `X-Lk-Sid` → Worker ходит в магазин с этой сессией; пропускаются те же пути, что и в `server.mjs`, POST только на `/sv-api/order`;
- `GET /config` → ключ поиска адреса Google (секрет `GOOGLE_PLACES_KEY`, если задан).
Запросы принимаются только с адресов из `ALLOWED_ORIGINS`. Сессия живёт час с последнего обращения. Токены, ссылки и значения кук не логируются.

Развернуть (нужен аккаунт Cloudflare, из каталога `coral-club-shop/packages/gateway/`):
```bash
npx wrangler login
npx wrangler kv namespace create SESSIONS      # выданный id подставьте в wrangler.toml
npx wrangler secret put GOOGLE_PLACES_KEY      # по желанию, поиск адреса Google
npx wrangler deploy                            # напечатает адрес вида https://coral-lk-checkout.<аккаунт>.workers.dev
```
Затем впишите этот адрес в `docs/config.json` (`"shopWorker"`) и запушьте. В `wrangler.toml` в `ALLOWED_ORIGINS` должен быть адрес вашего GitHub Pages (по умолчанию `https://bogdan787878.github.io`); для проверки с компьютера добавьте `http://localhost:3300`.
